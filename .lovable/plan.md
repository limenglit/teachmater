# 重新查找 iPhone 12–15 打不开签到页的原因（不做中转）

## 已核对的事实（本次回查结果）

- 后台连接库版本与 8 月 28 日完全相同（未升级）。
- 学生打开签到、提交签到所用的后台函数一直对未登录学生开放；9 月 22 日的收紧只涉及白板、投票、弹幕、文件存储，没有改动签到读取。
- 8 月 28 日后新增的程序库只有公式编辑器（KaTeX、拖拽），不在签到页里加载。
- 你截图里的「网络不稳定，签到页加载失败」说明：页面本身已打开，卡在「向后台取本次签到」这一步，而且现在的代码把所有失败原因都显示成同一句话，看不到真正的错误。
- 找到一个与机型高度相关的可疑点：登录组件在每次取数据前，会先用浏览器的「跨页面锁」检查登录状态。这一功能在部分 iOS 版本的微信内置浏览器里存在已知缺陷，可能导致请求一直排队、最终超时。新机（iPhone 16/17，通常是 iOS 18 / 26）不受影响，旧机常停留在较早的 iOS 版本，正好对应你描述的现象。此点尚未在真机上证实。

## 要做的事

### 1. 先拿到真机上的真实错误（必须）
- 签到页加载失败时，不再只显示「网络不稳定」，而是在下方显示一行小字诊断：系统版本、微信版本、失败在哪一步（锁等待 / 请求发出 / 后台返回 / 解析）、错误原文、耗时。
- 学生截图即可，你转给我就能定位，不需要任何额外操作。
- 同时把这些诊断悄悄记录到后台一张「扫码诊断」表里（成功和失败都记），便于按机型、系统版本统计。

### 2. 签到页彻底绕开「跨页面锁」
- 学生签到页（普通签到、座位签到）只用不检查登录状态的轻量连接（已部分完成），并确认页面打开时，全站的登录检查、功能开关读取等不会抢先占住锁、拖住签到请求。
- 签到页不再等待全站的登录初始化完成即可显示和提交。

### 3. 旧 iOS 解析兼容性体检
- 对正式打包后的签到页相关文件做一次「旧 iOS（15、16、17）语法与功能」扫描，列出任何旧系统不认识的写法，有则改写或补齐。
- 加一条自动测试：签到页相关代码不得出现旧 iOS 不支持的写法，防止以后再次引入。

### 4. 与 8 月 28 日方案的对照
- 输出一份对照清单：8 月 28 日签到页的加载流程与现在逐项对比（取数据方式、重试、登录检查、页面拆分、首屏资源），对所有与「旧机型」可能相关的差异，恢复为 8 月 28 日的做法。

## 需要你配合

## 技术细节
- `src/lib/scan-session.ts`：区分并记录错误类型（AbortError / TypeError fetch failed / PostgREST error code / lock timeout），返回 `{ kind:'network', diag }`；页面渲染 diag。
- 新表 `scan_diagnostics`（session_id、page、ua、ios_version、wechat_version、stage、error、elapsed_ms、ok、created_at），RLS：anon 仅可 INSERT 且字段长度受限，教师/管理员可查询；提交走轻量连接，失败不影响签到。
- 学生路由（`/checkin/:id`、`/seat-checkin/:id`）检查 `AuthContext` / `FeatureConfigContext` 的启动调用是否在同一时间触发主连接 `getSession`（navigatorLock），必要时对这两条路由跳过或延后。
- 用 `es-check`（目标 Safari 15）与浏览器兼容规则扫描 `dist` 中签到页入口与依赖分块；新增 vitest 用例约束。
- 不做任何后台中转或域名改动。
