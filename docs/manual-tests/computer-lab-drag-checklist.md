# 机房（ComputerLab）拖拽白屏回归测试清单

目的：验证机房场景下拖拽桌子（行）与人员（座位）不再触发白屏崩溃，并对边界条件具备容错能力。

## 前置准备
- 登录任意教师账号，进入「座位 → 机房」场景。
- 名单：分别用 0 / 1 / 30 / 60+ 学生的班级各测一次。
- 浏览器打开 DevTools → Console，全程观察无未捕获错误。
- 同时在桌面（鼠标）和移动端（触控）各跑一次完整流程。

## A. 桌子（整行）拖拽
| # | 步骤 | 期望结果 |
|---|------|---------|
| A1 | 点「自动排座」生成布局后，按住任一行的长桌横条拖动 | 行平滑跟随，不白屏，Console 无报错 |
| A2 | 拖动过程中快速松开 / 再次按下另一行 | 上一次拖拽干净结束，新行可继续拖 |
| A3 | 拖拽时鼠标移出预览区再回来 | 不残留 ghost、不白屏 |
| A4 | 拖动后点击行右侧「90°」按钮旋转 | 旋转生效，位置保留 |
| A5 | 拖到极端坐标（远离画布）后点「重置桌子位置」 | 全部归零，无崩溃 |
| A6 | 拖动中途修改「行数」「每桌座位数」「每行桌组数」「学生位置」 | 即便正在拖拽的行被裁掉也不白屏，松手后状态自洽 |
| A7 | 拖动中途切换历史记录还原 | 不白屏，恢复到目标快照 |

## B. 人员（座位）拖拽
| # | 步骤 | 期望结果 |
|---|------|---------|
| B1 | 拖动一名学生到同行同侧另一座位 | 两人交换，姓名正确 |
| B2 | 拖到不同行 / 不同侧（top↔bottom） | 交换成功 |
| B3 | 拖到空座位 | 学生迁移、原座位清空 |
| B4 | 拖到「关闭」的座位 | 不交换，dragFrom/dropTarget 复位 |
| B5 | 拖动中途松手在画布外 | 状态复位，无白屏 |
| B6 | 拖动一名学生时，同时另一手指开始拖动整行（移动端双指） | 不白屏；以先发起的拖拽为准 |
| B7 | 拖动过程中切换「学生位置」（仅上 / 仅下 / 双侧） | 即便目标侧被隐藏也不崩溃 |
| B8 | 拖动过程中减少「每桌座位数」使列号越界 | 受影响的座位安全丢回 prev，无白屏 |

## C. 参照物（黑板 / 窗 / 门）
| # | 步骤 | 期望结果 |
|---|------|---------|
| C1 | 勾选「锁定参照物」后尝试拖动 | 拖不动，无报错 |
| C2 | 解锁后将门拖到四个角 | 学生端导航 doorPosition 跟随更新 |
| C3 | 黑板拖动只在水平方向移动 | y 锁定在顶部 |

## D. 持久化与还原
| # | 步骤 | 期望结果 |
|---|------|---------|
| D1 | 拖动若干桌子和人员后刷新页面 | 布局完整恢复 |
| D2 | 「保存历史」→ 修改布局 →「还原历史」 | 选中快照精确还原，无白屏 |
| D3 | 删除当前选中的历史 | 列表更新，画布保持当前状态 |

## E. 错误兜底自检
- Console 中应不出现 `Cannot read properties of undefined`、`...is not iterable`、`Maximum update depth` 等错误。
- 若出现任意 `[ComputerLab] mousemove handler error` / `[ComputerLab] seat swap error` 日志：拖拽**仍应**自动恢复（refs 被清空、UI 不白屏），但需登记复现步骤反馈给开发。

## 通过标准
A、B、C、D 全部步骤均「无白屏 + 无未捕获 Console 错误 + 状态自洽」即视为通过。任一项失败需附带复现路径与截图。
