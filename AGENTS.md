
- (superseded) Class data spaces: boards/quiz_sessions/checkin_sessions/seat_checkin_sessions carry class_id; tag on create via set_content_class RPC and filter on load via src/lib/class-space.ts — keeps classes isolated without changing create RPCs.
- Seat chart exports restore only the outer room zoom, keep child transforms, and fit PDF onto one appropriately sized page — this prevents displaced labels and split seats in large rooms.
- Shared exports never generate or embed check-in QR codes; check-in codes belong to the separate check-in dialog, keeping every seat chart format QR-free.
- Every html2canvas call goes through renderCanvas in src/lib/export.ts, which keeps html2canvas's 1x1 baseline-probe img inline during capture; Tailwind preflight's img{display:block} otherwise draws all exported text several pixels low. Print-only chart content uses data-export-only (hidden on screen, revealed at chart width), and printed color swatches are text glyphs because html2canvas cannot paint currentColor backgrounds. Exporter-written text (chart title/footer, the whole PDF seat index page) is painted with native canvas text in src/lib/canvas-text.ts (measureText, per-character spacing, auto-shrink/truncate); html2canvas places glyphs from page measurements and overlaps them whenever the canvas font is wider. The DOM/exportTextCss path is only a fallback when canvas 2D is unavailable.
- Student quiz and practice content uses the shared MathText renderer for questions, options, answers and explanations; bounded formula-only scrolling preserves KaTeX geometry without clipping or overflowing the page.
- Formula block composition uses dnd-kit Pointer and Keyboard sensors without portal overlays, with a shared pure block serializer; this keeps touch, accessible reordering and inserted LaTeX consistent.
- Student scan pages (CheckInPage, SeatCheckinPage, scan-session) use src/lib/student-supabase.ts: no persisted session, same-domain API relay first with automatic direct fallback — keeps unauthenticated phones lightweight and reachable when the direct backend host is throttled in mainland China.
- Student scan routes render the separate StudentApp shell (chosen in src/routes/__root.tsx; teacher pages load TeacherShell) that uses language-core + generated per-page per-language src/lib/student-i18n/<page>-<lang>.ts loaded by student-i18n-loader, own small Tailwind CSS per page, and a fetch-only backend client (rerun bun scripts/gen-student-i18n.ts after adding t() keys to check-in pages); never import TeacherShell, LanguageContext or the main Supabase client there — keeps phone downloads small.
- Seat check-in first screen holds only the name form; submit logic (seat-checkin-submit), custom fields/OTP (SeatCheckinExtraFields), scan diagnostics (scan-diag) and the post-check-in seat view (SeatCheckinResult with its own CSS and seatResult dict) are dynamic imports, and shared student modules are merged into the student-core manual chunk — keeps the first download near 60KB gzip.
- The boot watchdog in src/lib/boot-scripts.ts (inlined into the root head) auto-reloads once with a ?_r= cache-buster when the entry module 404s, or has downloaded but not run by 25s, or still not run by 40s (never while the entry is still downloading at 25s), and logs boot-* rows to scan_diagnostics on scan routes; the head must never preload the app entry itself — stale cached HTML from WeChat WebViews otherwise leaves the whole site blank, and early reloads restart slow downloads.
- Scan routes rely on TanStack Start SSR emitting modulepreload links for the matched route chunks, and the scan skeleton is applied from the head script into #tm-boot (never a <script> rendered inside a React component) — removes the chunk waterfall on weak networks without client-side script warnings.
- Student scan reads use preflight-free GET rpc (apikey in query), a root-head inline hedged prefetch (window.__TM_PREFETCH__: second request at 350ms, at most 3, 9s cap) with a seconds-counting "do not close" skeleton, hedged requests and a ~60s retry budget with localStorage fallback — iOS WebKit drops cross-border connections fast and intermittently.

- Class filtering is per-page only ("按班级筛选"); there is no global top-bar class switcher and getActiveClassId() is always null — two filters conflicted and hid content.
- PDF seat index entries use the seat name printed on that room's chart (排/座 grid, table name, lab row bar); index pages render at a fixed A4-sized canvas mapped to the full sheet, with separate number/name/seat slots, JS name truncation and no overflow clipping on text — html2canvas ignores ellipsis and shifts clipped text, which caused overlap and inconsistent sizes.
- Teacher on-site make-up check-ins go through owner-checked RPCs (teacher_add_seat_checkin_record tags extra_fields 签到方式=教师补签; teacher_add_checkin_record sets checkin_records.checkin_method='teacher', which a BEFORE INSERT trigger forces back to 'scan' for any other insert); both skip OTP, work after the session ends and dedupe by name — direct inserts only accept active sessions and students must not forge the make-up label.
- All browser calls to the backend (auth/rest/storage/functions) are rewritten by src/lib/backend-proxy.ts to the same-origin relay src/routes/api/public/sb/$.ts, which only forwards those four path prefixes — teachers in mainland China reach login and data via teachermate.org.cn without a VPN. Realtime websockets and public storage file links still use the direct backend host.
- Student scan CSS files are precompiled with Tailwind v3 by scripts/build-student-css.sh (sources in scripts/student-css/); rerun it after changing classes on scan pages — keeps older iOS WebViews styled while the teacher app uses Tailwind v4.
